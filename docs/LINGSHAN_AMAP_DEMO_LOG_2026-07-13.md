# 灵山胜境前端演示与真实接口日志

日期：2026-07-13

## 一句话说明

现在的路线页以“灵山胜境”为主景区，景点、经纬度、步行距离和路线折线都由后端实时查询高德 Web 服务。没有使用 Mock（假数据）兜底；高德调用失败时，页面会直接说明失败原因。

## 小白版：数据是怎么来的

1. 浏览器只告诉后端：“我要看灵山胜境”或“帮我生成路线”。
2. 后端拿服务器里的高德 Key 去请求高德，不会把 Key 发给浏览器。
3. 高德返回真实 POI、坐标和步行路线。
4. 后端整理后再把结果显示到页面。

可以把它理解成：浏览器是游客，后端是导游，高德是地图资料库。游客不会直接拿到导游保管的钥匙。

## 演示入口

- 页面：`http://zjy666:8000/pages/recommend/index.html`
- 本地启动命令：`python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`

首次打开如果显示“需要登录”，任选“以团长身份体验”或“以游客身份体验”即可。真实景区路线不要求预先创建房间。

## 演示步骤

1. 打开路线页。
2. 确认页面显示“高德真实数据已连接”。
3. 查看“当前主景区”：应为“灵山胜境”。
4. 查看“拈花湾禅意小镇”：它会作为独立景区展示，不会混入灵山胜境步行路线。
5. 选择游览时间、体力和兴趣。
6. 点击“生成高德真实路线”。
7. 查看每个景点的 POI ID、经纬度、地址，以及相邻景点的步行距离和时间。

## 本项目提供的接口

- `GET /api/map/scenic-areas/current`：查询当前主景区、相关独立景区和真实 POI。
- `GET /api/map/scenic-areas/{scenic_area_id}/routes`：查询该景区可选路线模板，并用高德计算真实路线。
- `POST /api/recommend/route`：根据时间、体力和同行情况生成真实推荐路线。

后端实际调用高德的 POI 搜索 2.0 和步行路径规划 2.0 接口。

## 如何判断没有用 Mock

- 代码中的地图工厂只允许 `MAP_PROVIDER=amap`。
- 没填 Key 时接口返回明确错误，不会给出一组看起来正常的假坐标。
- 高德超时、限流或返回错误码时，后端返回 502/503，并记录不含 Key 的技术日志。
- 页面会显示数据来源“高德地图 Web 服务”，路线结果会包含高德 POI ID 和折线坐标点数量。

## Key 安全说明

- Key 只从根目录 `.env` 的 `MAP_API_KEY` 读取。
- 前端 HTML、JavaScript、接口响应和本日志都不包含 Key。
- 后端日志只记录接口名称、尝试次数和结果数量，不记录完整请求地址或 Key。

## 常见问题

### 页面一直显示“正在连接高德地图”

先确认后端正在运行，再刷新页面。还不行时查看后端是否能访问 `restapi.amap.com`。

### 页面提示“未取得真实地图数据”

检查 `.env` 中是否填写 `MAP_API_KEY`，以及该 Key 是否开通“Web 服务 API”。系统不会改用 Mock 数据。

### 点击路线按钮提示失败

先确认已经通过登录弹窗进入体验。如果高德返回配额、权限或网络错误，后端会给出明确错误；稍后重试或检查高德控制台即可。
