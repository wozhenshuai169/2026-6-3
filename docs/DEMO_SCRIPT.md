# 云游智导答辩演示脚本

建议总时长：7 分钟。演示前启动服务并预先打开游客端、导游端、管理端三个标签页。

## 0:00-0:40 开场与问题

讲解词：

“我们交付的是面向灵山胜境的本地智能导游系统。它解决三个现场问题：游客需要个性化且可信的讲解，导游需要兼顾团队广播与个体需求，景区管理者需要看到服务反馈并及时发布运营信息。系统在一台电脑上即可运行，游客主要页面按手机竖屏设计。”

画面：打开首页，进入游客端，展示竖屏布局和灵山胜境品牌入口。

## 0:40-2:00 个性化路线

操作：选择亲子、历史文化或少走路偏好，生成推荐路线。

讲解词：

“路线推荐综合游客兴趣、同行人群、体力和当前游览状态。这里选择亲子偏好，系统会优先九龙灌浴、百子戏弥勒、梵宫与五印坛城，并展示推荐理由。路线距离来自简化演示图，不冒充园区测绘数据。”

验收点：路线卡片、推荐理由、景点顺序、竖屏无横向溢出。

## 2:00-3:20 语音问答与数字人

操作：点击录音并说“灵山大佛有多高”，等待识别、回答和播报。

讲解词：

“语音首先由 Qwen ASR 识别，再进入有来源约束的景区知识检索，最后由 TTS 播报。男性卡通数字人会在闭口与开口两帧间切换，口型节奏与音频能量联动。任何外部服务失败都会明确报错，不用伪造结果掩盖故障。”

验收点：识别文本、88 米回答、引用来源、音频播放、男性数字人口型切换。

## 3:20-4:10 图片识景

操作：上传一张灵山大佛或九龙灌浴图片。

讲解词：

“图片识景使用视觉模型返回候选景点和置信度，再与本地景点库校验。低置信度或非灵山图片不会强行命名，而是提示补拍或人工确认。”

验收点：图片预览、识别结果、置信度、景点讲解衔接。

## 4:10-5:10 导游协作与安全

操作：切换导游端，展示房间广播、讲解状态、消息与运营提示。

讲解词：

“导游可以统一控制讲解与团队消息。游客的普通问题私密回答；走失、身体不适等场景会按授权规则通知领队。运营事件可覆盖临时封路、天气和客流提醒，实时信息优先于静态知识。”

验收点：团队房间、广播、讲解控制、事件提示和权限边界。

## 5:10-6:10 管理与数据治理

操作：打开管理端知识库和看板，展示来源字段与数据质量文档。

讲解词：

“我们保留了项目原有的拈花湾扩展知识和候选设施位置，同时重点完善灵山胜境。审计发现行为 Excel 只有 0.37% 与灵山相关、714 行消费合计不一致，两份 Word 无来源且互相矛盾。因此系统区分官方核验、内部安全规则和待核验参考；候选设施仍可用于演示导航，但会明确提示以现场标识为准。”

验收点：知识条目、来源引用、运营看板、`docs/SOURCE_DATA_QUALITY.md`。

## 6:10-7:00 交付总结

讲解词：

“项目以 FastAPI、SQLite 和原生移动 Web 组成，支持一键本地启动、健康检查、认证、WebSocket 协作、语音、视觉、路线与管理闭环。当前自动测试 53 项通过，9 个主要页面完成 390 乘 844 竖屏验收。系统明确保留单机版边界，便于评委在自己的电脑上复现。”

画面：展示测试结果、竖屏九宫格截图和本地启动入口。

## 演示故障预案

- 外部模型网络不稳定：展示已保存的 `qa/mobile-portrait/` 截图和自动测试结果，再说明接口的明确降级提示。
- 麦克风权限被浏览器拒绝：改用准备好的本地音频文件上传。
- 图片识别超时：使用灵山大佛测试图重试一次，不连续点击。
- 端口 8000 被占用：运行 `start.bat 8010`。
- 数据库已有旧演示数据：停止服务，备份后删除 `data/app.db`，再重新启动生成干净库。
